# الدليل الشامل لمشروع منصة الاختبارات الذكية (Master Guide)

هذا المستند هو المرجع التقني الكامل للمشروع، تم إعداده خصيصاً لمناقشة التخرج. يحتوي على شرح تفصيلي للكود، الميزات، والقرارات التقنية للإجابة على أسئلة لجنة المناقشة بدقة.

---

## 1. نظرة عامة وتقنيات المشروع (Project Overview)

### التقنيات المستخدمة (Tech Stack)
*   **Backend:** Python, Django 5.0 (إطار عمل قوي وآمن).
*   **Frontend:** HTML5, TailwindCSS (تصميم عصري ومتجاوب)، JavaScript (للتفاعل اللحظي).
*   **Database:** SQLite (للتطوير) / PostgreSQL (للإنتاج).
*   **AI Integration:** Ollama (تشغيل نماذج الذكاء الاصطناعي محلياً لضمان الخصوصية).
*   **Security:** Django Security Middleware, CSRF Protection, 2FA.

### هيكلية المشروع (Architecture)
يعتمد المشروع على نمط **MVT (Model-View-Template)** الخاص بـ Django:
*   **Models:** تعريف جداول قاعدة البيانات (الطلاب، الامتحانات، الأسئلة).
*   **Views:** المنطق البرمجي (معالجة الطلبات، الذكاء الاصطناعي، منع الغش).
*   **Templates:** واجهات المستخدم (Dashboard، صفحة الامتحان).

## 3. شرح مفصل للميزات (للإجابة الشفوية)

### 1. كيف يعمل نظام منع الغش تقنياً؟
"نستخدم تقنية **DOM Event Listeners** في المتصفح. عندما يقوم الطالب بتبديل التبويب، يطلق المتصفح حدث `visibilitychange`. يلتقط الكود لدينا هذا الحدث ويرسل طلب **AJAX** غير متزامن للسيرفر لتسجيل المخالفة في جدول `ExamEvent`. إذا تكرر الأمر، يقوم كود JavaScript محلياً بقفل الشاشة."

### 2. كيف تم ربط الذكاء الاصطناعي؟
"لم نستخدم API خارجي مدفوع (مثل OpenAI) للحفاظ على الخصوصية وتقليل التكلفة. استخدمنا **Ollama** لتشغيل نموذج Llama 3 محلياً. التحدي الأكبر كان جعل الذكاء الاصطناعي يلتزم بصيغة بيانات محددة، وحللنا ذلك عبر **Prompt Engineering** دقيق يطلب الرد بصيغة JSON حصراً، ثم نقوم بمعالجة الرد (Parsing) في الباك إند."

### 3. كيف تضمنون أمان الامتحانات؟
"نطبق الأمان على عدة مستويات:
1.  **المصادقة (Authentication):** تأكيد الهوية عبر 2FA.
2.  **الصلاحيات (Authorization):** الطالب لا يمكنه رؤية الامتحانات إلا إذا كان عضواً في المجموعة الدراسية (`StudentJoinRequest`).
3.  **النزاهة (Integrity):** الأسئلة والخيارات تخزن مشفرة، والوقت يحسب من السيرفر (`computed_end_time`) لمنع تلاعب الطالب بساعة جهازه."

### 4. كيف تعمل المجموعات الدراسية (Study Groups)؟
"هي علاقة Many-to-Many بين الطالب والمعلم. المعلم ينشئ 'مجموعة'، والطالب يرسل 'طلب انضمام' (`StudentJoinRequest`). المعلم يجب أن يوافق على الطلب ليتمكن الطالب من رؤية الامتحانات الخاصة بهذه المجموعة. هذا يضمن عدم دخول غرباء للامتحان."

## 4. مخطط قاعدة البيانات (Database Schema Brief)

أهم الجداول التي بني عليها المشروع:
1.  **User:** مستخدم مخصص (Custom User Model) يدعم الأدوار (طالب، معلم، مشرف).
2.  **Exam:** تفاصيل الامتحان (العنوان، المدة، وقت البدء، إعدادات المراقبة).
3.  **Question:** الأسئلة (نص السؤال، النوع، الدرجة، الصعوبة).
4.  **StudentExam:** ورقة إجابة الطالب (تربط الطالب بالامتحان وتحفظ النتيجة).
5.  **ExamEvent:** سجل أحداث المراقبة (الغش، دخول/خروج) لكل محاولة امتحان.
